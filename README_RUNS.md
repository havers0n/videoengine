# Run-Based Организация R&D Проекта

## Проблема

Ранее все варианты складывались в одну папку `data/`, что приводило к:
- Невозможности отследить, какой промпт какой вариант сгенерировал
- Невозможности сравнивать прогоны между собой
- Загрязнению основной папки
- Проблемам с поиском файлов в вариантах

## Решение: Run-Based Структура

Теперь каждый прогон генерации — это отдельный артефакт в `runs/`.

### Структура

```
/runs/
  2025-12-29_01/          # Run с датой и временем
    prompt_01.txt          # Промпты для генерации
    prompt_02.txt
    zips/                  # Исходные zip-файлы
    extracted/             # Распакованные варианты
    variants/              # Нормализованные варианты
    reports/               # Результаты анализа
      variants_features.json
      variants_features.csv
      run_report.md
    mapping.json           # Маппинг zip → variant → prompt

/master/
  dataset.json             # Агрегированный датасет всех runs
  ignore.json              # Глобальный ignore list
  scoring.json             # Версионированные веса scoring
```

## Использование

### 1. Миграция Legacy Данных

Если у вас есть данные в `data/`, мигрируйте их:

```bash
npm run migrate:legacy
```

Это:
- Скопирует все варианты из `data/` в `runs/legacy_01/extracted/`
- Нормализует их в `runs/legacy_01/variants/`
- Запустит анализ
- Создаст baseline `master/dataset.json`

### 2. Новый Run

1. Создайте директорию run:
   ```bash
   mkdir runs/2025-12-29_01
   ```

2. Поместите zip-файлы в `runs/2025-12-29_01/zips/`

3. (Опционально) Создайте файлы промптов:
   ```
   runs/2025-12-29_01/prompt_01.txt
   runs/2025-12-29_01/prompt_02.txt
   ```

4. Запустите ингест:
   ```bash
   npm run ingest -- runs/2025-12-29_01
   ```

Скрипт автоматически:
- Распакует zip-файлы
- Нормализует варианты
- Запустит анализ
- Создаст отчеты
- Добавит результаты в `master/dataset.json`

### 3. Анализ

Анализ вариантов выполняется автоматически при ингесте. Для ручного анализа:

```bash
# Анализ всех вариантов в директории
npm run analyze -- runs/2025-12-29_01/variants

# Обработка результатов
npm run process:stats -- runs/2025-12-29_01/reports/variants_features.json
```

## Улучшения

### 1. Поиск Файлов

Исправлен поиск файлов в `analyze-variants.mjs`:
- ✅ Рекурсивный поиск всех `**/*.{ts,tsx}`
- ✅ Игнорирование мусора (node_modules, dist, .next, build, etc.)
- ✅ Проверка наличия ключевых файлов (App.tsx, main.tsx, src/)

### 2. Нормализация Вариантов

Скрипт ингеста автоматически:
- Определяет структуру проекта (по наличию App.tsx/main.tsx/src/)
- Копирует только нужные файлы
- Игнорирует мусор

### 3. Маппинг Промптов

Каждый run сохраняет `mapping.json` с:
- Какие zip-файлы были обработаны
- Какие промпты использовались
- Связь между zip → variant → prompt

## Master Dataset

`master/dataset.json` содержит агрегированные данные всех runs:
- Все фичи вариантов
- `run_id` - из какого run вариант
- `ingested_at` - дата добавления

Используйте для:
- Анализа трендов по времени
- Сравнения runs
- Генерации новых промптов на основе корреляций

## Конфигурация

### master/ignore.json

Глобальный список вариантов и паттернов для исключения из анализа.

### master/scoring.json

Версионированные веса для scoring. Изменения должны быть обоснованы.

## Проблемы и Решения

### "Скрипт не находит файлы"

Убедитесь, что:
- Вариант содержит хотя бы один из: `App.tsx`, `main.tsx`, `index.tsx`, или файлы в `src/`
- Нет проблем с правами доступа
- Структура варианта не слишком вложенная

### "Ошибка при распаковке zip"

Проверьте:
- Zip-файл не поврежден
- Есть права на запись в `extracted/`
- Имя zip-файла не содержит недопустимых символов

### "Вариант не добавился в master dataset"

Проверьте:
- Анализ завершился успешно (см. `reports/variants_features.json`)
- Нет дубликатов (вариант с таким же именем уже есть в master)
